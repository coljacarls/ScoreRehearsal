# ScoreRehearsal

A lightweight, read-only rehearsal player for MuseScore files (`.mscz`, `.mscx`), built from
[MuseScore Studio](https://github.com/musescore/MuseScore) components.

Open a score, tap a beat to move the playhead, play, pause, use the metronome, mute or solo tracks
and balance them against an "accompaniment" fader, switch between page and continuous view, and go
full screen for rehearsing on a touch device. The score file is never modified.

## Repository layout

```
build.cmd                 Windows build script (MSVC + Ninja + Qt 6)
src/
  appshell/               the application shell: window, rehearsal page, commands (C++ / QML)
  cmake/Configure.cmake   which MuseScore modules are built, branding
  cmake/App.cmake         executable name, icon, app resources
  app/app.qrc.in          app resources (themes, shortcuts) taken from the MuseScore tree
  branding/               icon (generated by make_icon.py), no MuseScore assets
musescore/                git submodule: fork of MuseScore Studio, branch "rehearsal-app"
  muse/                   git submodule: fork of the Muse framework
```

The MuseScore submodule is the real build root. MuseScore knows several *build configurations*
(`app`, `app-portable`, `app-web`, ...); the fork adds **`app-external`**, which builds a shell
that lives outside the MuseScore tree. `build.cmd` configures MuseScore with

```
-DMUSESCORE_BUILD_CONFIGURATION=app-external -DMUE_EXTERNAL_APP_DIR=<this repo>/src
```

and MuseScore then includes `src/cmake/Configure.cmake`, adds `src/appshell` in place of its own
`appshell` module and links everything into `ScoreRehearsal.exe`. Nothing of ScoreRehearsal is
compiled into MuseScore Studio itself.

### What the fork branch contains

The branch `rehearsal-app` of the MuseScore fork differs from upstream only in:

- the rehearsal view core (session-only mix and solo state in `PlaybackController`,
  `RehearsalTracksPanel`, tap-to-seek and `viewModeOverride` in the notation view), plus the
  "Rehearse" tab of the full MuseScore app;
- the generic `app-external` hooks: a block in `SetupConfigure.cmake`, one `elseif` in
  `src/CMakeLists.txt`, a few lines in `src/app/CMakeLists.txt`, `src/app/app_config.h.in` and
  `src/app/main.cpp`;
- a two-line ASIO build fix in the Muse framework submodule.

## Building (Windows)

Requirements: Visual Studio 2022 Build Tools (C++ toolchain, CMake and Ninja components),
Qt 6.11 for MSVC 2022 (default location `C:\Qt\6.11.2\msvc2022_64`, override with the
`QT_DIR` environment variable), Python 3 (MuseScore build scripts), git.

```
git clone --recurse-submodules https://github.com/coljacarls/ScoreRehearsal.git
cd ScoreRehearsal
build.cmd install Release
build\Release\install\bin\ScoreRehearsal.exe path\to\score.mscz
```

`build.cmd configure|build|install|run|clean [Release|Debug|RelWithDebInfo]`; the install step
runs `windeployqt`, so `build\<type>\install` is a complete, relocatable application directory.

## Updating the MuseScore dependency

MuseScore is pulled in through the submodule, so updating is a merge in the fork plus a pointer
update here:

```
cd musescore
git fetch upstream
git merge upstream/master                # resolve conflicts in the few patched files, if any
git push origin rehearsal-app
cd muse                                   # only if upstream moved the muse submodule
git fetch upstream && git merge upstream/main && git push origin rehearsal-app
cd ../..
build.cmd install Release                 # rebuild and smoke-test
git add musescore && git commit -m "Update MuseScore to <date>"
```

After a merge, compare `src/cmake/Configure.cmake` with the `APP-WEB` block in
`musescore/SetupConfigure.cmake` and the option lists in `musescore/CMakeLists.txt` and
`musescore/muse/framework/cmake/MuseDeclareOptions.cmake`: new module options should be switched
off explicitly unless the app needs them.

## Behaviour

- Starts in the dark theme (switchable in the `…` menu); the choice is remembered.
- Scores open in the continuous (horizontal) view; page view is available from the view button.
- Scores are never saved: no autosave, no "save changes?" prompt, no migration dialog for files
  from older MuseScore versions (they are shown as saved).
- No network access: no update checks, no cloud, no MuseSounds / Muse Hub.

## Keyboard shortcuts

MuseScore's default shortcuts apply where the commands exist: `Space` play/pause, `Ctrl+O` open,
`F11` full screen, `Ctrl+Q` quit. Closing a score is in the `…` menu.

## About me and the "why"
I am a 40-something year old family father with a background in computer science and usability.
I LOVE music, love arranging it and in MuseScore I found my go-to-software, especially since the
overhaul led by Martin Keary (aka. Tantacrul). Thanks for making MuseScore a no-brainer with
premium usability!

In my spare-time I often take the role of a conductor for vocal groups. Because I s*ck at playing
the piano I tend to use the playback function of MuseScore to play the score, set the focus on
single voices, scrub through the chords to help the group find their place in the harmony.
Unfortunately MuseScore has no focus on tablets (yet) and opening a score and using it for the
porposes of the rehursal sometimes messes up the score. Everything needs to happen fast to keep
the drive in a rehursal:
- switching the playback between single voices
- starting the playback at selected measures or beats
- mixing the volume levels for certain voices in focus with "the rest"
- and everything without messing with the score underneath.

MuseScore unfortunately gave me multiple headaches in the past. Although it is the tool I always
wanted for writing scores (except for one or two things) it is very imperfect for working with the
scores the way I do during a rehursal, as my digital pianist.
This is the reason why the idea of this software exists.
When it comes to writing code, my focus is strongly on web technology and I think I won't become an
expert in C++ and Co. in the near future. My first idea was to make a pull request in the MuseScore
project for a "Rehurse" tab, right between the "Score" and the "Publish" tab. But my lack in understanding
the programming languages needed, I'd never be able to go through the process.
This is why opened this side-project with a forked MuseScore to build on.
And yes: the development is AI-first.
